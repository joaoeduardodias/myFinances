# Web Push dos avisos — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entrega 2 do consultor. Cada aviso novo gravado por `checkAlerts` também chega como notificação do navegador, mesmo com o app fechado (alvo: o computador).

**Architecture:** A API guarda as inscrições de push por usuário e envia com a lib `web-push` (VAPID). `checkAlerts` passa a gravar com `createManyAndReturn` e dispara o envio só dos avisos que acabaram de nascer, sem esperar (não segura a fila nem a resposta). No web, um service worker estático (`public/sw.js`) mostra a notificação e abre o app no clique; o sininho ganha o botão de ativar.

**Spec:** `docs/superpowers/specs/2026-10-27-consultor-ia-design.md` (objetivo 3).

## Global Constraints

- Push é acessório: sem as três `VAPID_*` fica desligado, e falha de envio nunca derruba `checkAlerts` nem a gravação do aviso.
- O aviso continua guardado no servidor; o push só replica. O app React Native vai consumir os mesmos avisos.
- Inscrição expirada (404/410 do serviço de push) é apagada.
- O `endpoint` é único: inscrever de novo no mesmo navegador com outro usuário move a inscrição para ele. Sair da conta remove a inscrição daquele navegador.
- Sem dependência nova no web: Push API e service worker são nativos.

## Review Focus

1. Aviso repetido (`skipDuplicates`) não gera push de novo. Teste na Task 2.
2. Remover inscrição só apaga a do próprio usuário. Teste na Task 3.
3. `sendPush` com falha de rede ou 410 não lança. Teste na Task 2.
